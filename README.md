# القادسية للتجارة · مواد خام البلاستيك

نظام عربي لإدارة الخامات والمخزون والموردين والعملاء وحركات التوريد والبيع. يعمل محليًا باستخدام SQLite، ويمكن نشر الواجهة وواجهة Python البرمجية على Vercel باستخدام قاعدة Neon PostgreSQL.

## التشغيل المحلي

يتطلب Python 3.10 أو أحدث، ولا يحتاج إلى حزم خارجية للتشغيل المحلي:

```powershell
python server.py --create-admin
python server.py
```

أدخل اسم المستخدم والاسم الظاهر وكلمة مرور لا تقل عن 12 حرفًا عند إنشاء المدير الأول، ثم افتح `http://127.0.0.1:8000`. تُحفظ قاعدة SQLite في `raw_materials.db` بجانب `server.py`.

## النشر على Vercel مع Neon

يكتشف Vercel تطبيق FastAPI من `server.py` ويخدم الملفات الثابتة من `public/`. ينشئ `build.py` نسخة النشر من `index.html` و`app.js` و`app.css` وشعار الشركة. قاعدة البيانات السحابية تُختار عند وجود `DATABASE_URL`؛ إذا غاب المتغير على Vercel، يتوقف الخادم برسالة واضحة ولا ينشئ قاعدة SQLite مؤقتة قد تفقد البيانات.

1. اربط مستودع GitHub بمشروع Vercel واجعل الفرع `main` هو فرع الإنتاج.
2. أضف تكامل Neon إلى مشروع Vercel، واختر قاعدة PostgreSQL للمشروع. تأكد من وجود متغير `DATABASE_URL` في بيئة Production، ثم أعد النشر.
3. لإعداد أول مدير، أضف مؤقتًا إلى بيئة Production المتغيرات التالية في Vercel:
   - `INITIAL_ADMIN_USERNAME`: اسم المستخدم، 3 أحرف على الأقل.
   - `INITIAL_ADMIN_DISPLAY_NAME`: الاسم الظاهر.
   - `INITIAL_ADMIN_PASSWORD`: كلمة مرور قوية، 12 حرفًا على الأقل.
4. أعد النشر. عند أول اتصال، ينشئ النظام الجداول والمخزن الرئيسي وحساب المدير مرة واحدة. بعد التأكد من وجود الحساب، احذف متغيرات `INITIAL_ADMIN_*` من Vercel وأعد النشر؛ بيانات الحساب تظل محفوظة في Neon.
5. افتح رابط Vercel وسجّل الدخول. أنشئ حسابات الموظفين من صفحة «فريق العمل».

لا تضع كلمات المرور أو `DATABASE_URL` في المستودع أو ملفات الواجهة. مستودع Git لا يحتوي قاعدة SQLite المحلية؛ البيانات التجارية لا تنتقل تلقائيًا إلى Neon. قاعدة العمل المحلية الحالية تحتوي حساب مدير فقط ولا تحتوي خامات أو حركات.

## الوظائف

## الوظائف الحالية

- تسجيل دخول منفصل، تجزئة كلمات المرور، جلسات محفوظة في قاعدة البيانات، وتحديد محاولات الدخول.
- دور مدير وموظف، وصلاحيات تشغيلية يحددها المدير عند إنشاء الموظف.
- إرجاع سعر البيع للمدير فقط؛ تختبر اختبارات HTTP أن السعر لا يظهر للموظف في واجهات المواد أو الحركات، وأن نقاط التقارير والإدارة مرفوضة.
- مواد وموردون وعملاء ومخزن رئيسي، وحركات توريد وبيع تسجل معها الكمية والمستخدم والتاريخ والتكلفة.
- بحث عن الخامات وفتح بطاقة تفصيلية تعرض بيانات المادة والمورد المرتبط وسجل مصادر التوريد والتكلفة والتاريخ والملاحظات، مع إخفاء سعر البيع عن الموظف في استجابة الخادم.
- معاملات لمنع الخصم المتزامن فوق الكمية المتاحة، ومفتاح `Idempotency-Key` لمنع تكرار حركة الإرسال.
- سجل تدقيق لمحاولات الدخول والحركات والإضافات. في النشر السحابي، تُدار النسخ الاحتياطية والاستعادة من إعدادات Neon.
- لوحة مدير وتقارير لفترة زمنية، مع تصدير CSV وطباعة المتصفح.

## الحدود الحالية قبل الاستخدام التشغيلي

هذه نسخة أولية لإدارة المخزون وليست ERP محاسبيًا كاملًا. لا تشمل حاليًا فواتير كاملة أو مدفوعات وحسابات دائنة أو تكلفة شحن وجمارك موزعة، ولا استعادة النسخة الاحتياطية من داخل الواجهة. راجع صلاحيات Vercel وNeon ونفّذ تشغيلًا تجريبيًا ببيانات العمل قبل الاعتماد المالي.

## الفحوص

```powershell
python -m py_compile server.py test_server.py
python -m unittest -v test_server.py
node --check app.js
```

الاختبارات المحلية تستخدم قاعدة مؤقتة ولا تعدل قاعدة العمل.
